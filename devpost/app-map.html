Repo Context Packager

A local TypeScript CLI that scans a project, ranks likely-relevant files with explainable heuristics, and saves a compact context package for an AI coding workflow.

One run, end to end

  1. CLI options
  2. Scan files and Git changes
  3. Rank with task and structure clues
  4. Package whole files within the budget
  5. Print and save Markdown or JSON

The scan stays on the local machine. Git is optional; when it is unavailable, task and structural clues still drive selection.

Reference route through the code

This is a navigation guide, not a claim that these files were toured interactively.

  1. src/cli.ts — parseOptions() validates flags; main() coordinates the run and writes the artifact.
  2. src/scanner.ts — scanRepository() gathers eligible files and optional Git status. Then src/ranker.ts — rankFiles() assigns task, structural, change, and neighbor reasons.
  3. src/packager.ts — packageContext() selects complete files and estimates serialized tokens. src/formatters.ts renders Markdown or JSON.

To change this, start here

  • CLI flags, validation, errors, and artifact destination: parseOptions() and main().
  • Ignored paths, eligible files, and Git status: isExcludedFile() and scanRepository().
  • Task relevance, structural tie-breakers, and diff neighbors: rankFiles(); coverage is in test/ranker.test.ts.
  • Token estimates, whole-file caps, and omission reasons: estimateTokenCount() and packageContext(); coverage is in test/packager.test.ts.

A practice to reuse

Early hands-on feedback found that structural-only files could appear even when a task was supplied. The task-matching test in test/ranker.test.ts now asserts that task matches govern selection, and rankFiles() implements that contract. On another project, turn a concrete user observation into an observable acceptance rule, then keep it from regressing with a focused test.
